# Plain-Code

我是不懂代码的初中生。这套规矩是用来管 AI 的。

AI 会装懂。它会说测过了，其实一下都没跑。它会修一个按钮，顺手把旁边的功能改坏。它还会编一个看起来像真的名字，拿去一跑才发现根本没有。

下面 5 份文件，就是用来堵住这些的。每条都是「必须」或「禁止」。

## 五份文件各管什么

[01-底线与通用.md](01-底线与通用.md)  
任何时候都先看。先把任务说清楚，我点头了再写。只改我点名的地方。说测过了，就必须拿出真实的运行记录。

[02-前端与气质.md](02-前端与气质.md)  
做页面时看。按钮要点得动，慢了要显示「加载中」，不许白屏。圆角、颜色、字号、留白都有固定数字，不许做成地摊货。

[03-后端与数据.md](03-后端与数据.md)  
写 Python、做窗口、动数据库时看。空数据直接打回。文件不在要说人话，不许闪退。删除必须确认三遍，不许一句话把仓库删掉。

[04-Rust专属.md](04-Rust专属.md)  
写 Rust 时加看。每种结果都要处理到。出错必须说清哪一段坏了。不许把报错藏起来。

[05-管理动作.md](05-管理动作.md)  
管你自己怎么开口。一个功能一个新对话。骂完的话要收成新规矩，不许只骂不记。

## 怎么用

新开一个对话，第一句就发：

`@Plain-Code 读我的规矩，这次任务是：[一句话]`

一个功能开一个对话。不要让一个对话干三件事。
